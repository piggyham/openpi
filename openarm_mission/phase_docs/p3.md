# P3 · 真实接触任务与成功判定

> 状态：✅ 已完成
> 作用：把 P2 的“确定性锁存展示”升级为**真实物理接触任务**——纸杯靠 MuJoCo 接触
> 和 weld equality 被夹起、搬运、释放；任务用状态机管理，区分成功/失败，并随机化
> 初始条件。这一步才真正“可评测”。

## 1. 这一步要做什么

1. 把任务写成 LIBERO 风格 BDDL，并通过 LIBERO 解析器。
2. 用**双指接触门控 + MuJoCo weld equality** 替代 P2 的展示锁存。
3. 设置 2 mm 杯壁/杯底，调整夹爪接触、摩擦、solver、自由杯体阻尼。
4. 实现右手稳定夹取、weld 误差和抓取丢失检测。
5. 实现中央稳定放置、右手无接触、左手再抓取判定。
6. 实现蓝区、直立 <20°、双手释放的最终成功判定，并连续保持 0.5 s。
7. 实现掉桌/过度倾倒/超时/双 weld/非有限状态等失败判定。
8. 在 A 区随机化纸杯位置、yaw、质量、摩擦。
9. 保存 success/failure 视频、事件时间线、分阶段指标。

核心实现：`openarm_mission/task.py`（状态机 + 门控 + 判定）和
`openarm_mission/p3_episode.py`（episode 运行器 + 视频/JSON 导出）。

## 2. LIBERO 风格 BDDL

`openarm_mission/bddl/openarm_v1_bimanual_paper_cup_relay.bddl` 用 LIBERO 的 BDDL
语法定义三区域（`red_a_region`、`center_handoff_region`、`blue_b_region`，坐标相对
`mission_table`）、夹具 `mission_table`、物体 `paper_cup_1`。`(:init)` 为纸杯位于
红区，`(:goal)` 为纸杯位于蓝区（`On ... blue_b_region`）。双臂顺序和中间状态由 P3
运行时状态机强制执行，BDDL 只描述目标态。已通过 LIBERO 自带解析器验证。

## 3. 状态机：`RelayStage`（`task.py:17`）

```
WAIT_RIGHT_GRASP → RIGHT_ATTACHED → RIGHT_LIFTED → WAIT_CENTER_STABLE
→ WAIT_LEFT_GRASP → LEFT_ATTACHED → LEFT_LIFTED → WAIT_GOAL_STABLE → SUCCESS
任何阶段可 → FAILURE
```

- `OpenArmRelayTask` 持有当前 `stage`、`failure_reason`、`events` 时间线、
  `_stage_durations` 分阶段耗时。
- `TERMINAL_STAGES = {SUCCESS, FAILURE}`；`done`/`success` 属性据此判断。
- 每次 `_transition` 记录上一阶段累计耗时并 emit 一条 `TaskEvent`。

## 4. 随机化 reset：`reset(seed)`（`task.py:188`）

用 `np.random.default_rng(seed)` 确定性地随机化：
- A 区内 `initial_xy_randomization_radius=0.015` 的均匀圆盘偏移（用
  `r*sqrt(U)` 保证面内均匀）。
- yaw 在 `[-π, π]` 均匀。
- 质量 scale `0.85~1.15`，同步缩放 `body_mass` 和 `body_inertia`。
- 滑动摩擦 `1.5~2.2`（写 `geom_friction[0]`）。
- 关闭两个 weld，`qvel` 清零，`mj_forward`。记录 `randomization` 字典。

## 5. 接触门控 weld 抓取：`grasp_gate` / `try_attach`（`task.py:294`、`task.py:326`）

这是 P3 与 P2 最核心的区别。**激活 weld 前必须通过双侧接触门控**，`grasp_gate`
要求**同时**满足：

1. 当前阶段正确（右手 `WAIT_RIGHT_GRASP` / 左手 `WAIT_LEFT_GRASP`）。
2. 未结束。
3. `finger_contacts(side)` 恰好返回 **2 个**手指（左指 + 右指都接触杯体）——
   `finger_contacts` 遍历 `data.contact`，取与 `_cup_geom_ids` 相交且属于该侧
   指面/指垫 geom 的接触。
4. `gripper_opening(side) ≤ grasp_opening_max=0.039`（夹爪够闭合）。
5. TCP 与杯体水平距离 ≤ `grasp_horizontal_tolerance=0.045`。
6. TCP 相对杯体的竖直偏移落在 `grasp_vertical_offset_range=(0.045,0.105)`。
7. 杯体倾角 ≤ `upright_limit_deg=20°`。

`try_attach`：先 `mj_forward` 刷新接触，再 `grasp_gate`。通过后：
- 从当前物理状态算杯子相对 TCP 的 `relpose`（`_relative_cup_pose`，`task.py:275`），
  写入 `model.eq_data[equality_id, 3:6]`（相对位置）和 `[6:10]`（相对四元数）。
  **不瞬移到预设姿态**，从实际状态接管。
- 把左/右 weld 都置位（只激活当前 side），`mj_forward`。
- 转移到 `RIGHT_ATTACHED`/`LEFT_ATTACHED`，记录 `grasp_attached` 事件。
- 拒绝则记录 `grasp_rejected`，返回 False（P4 据此触发后撤重试）。

> weld 激活后，杯子完全由 MuJoCo equality 推进，**P3 不再逐帧写杯体 free-joint 位姿**。
> `torquescale=0.05` 让 weld 力温和，避免硬拽翻杯子。

## 6. 释放：`release(side)`（`task.py:366`）

释放同样有门控，要求：
- 阶段在 `{RIGHT_ATTACHED, RIGHT_LIFTED}`（右）或 `{LEFT_ATTACHED, LEFT_LIFTED}`（左）。
- 当前 weld 激活。
- 杯子在目标区域内：右手目标是 `handoff_center`，半径 `handoff_radius=0.033`；
  左手目标是 `region_b_center`，半径 `goal_radius=0.048`。
- 倾角 ≤ 20°。
- 夹爪开度 ≥ `release_opening_min=0.034`（已张开）。
- 杯体 `_stable()`（线速度 ≤ `0.04 m/s`、角速度 ≤ `0.75 rad/s`）。

通过则关闭该侧 weld，`mj_forward`，转入 `WAIT_CENTER_STABLE`（右）或
`WAIT_GOAL_STABLE`（左），记录 `released`。

## 7. 每帧判定：`update()`（`task.py:457`）

物理步进后调用，按优先级检查失败，再推进状态：

失败检查（任一命中即 `fail(reason)` 并关 weld）：
- `qpos`/`qvel` 非有限 → `non_finite_state`。
- 超时（`timeout_seconds=35`）→ `timeout`。
- 左右 weld 同时激活 → `both_welds_active`（任意时刻最多一个）。
- 杯底低于桌面 `table_top_z - drop_below_table_margin(0.035)` →
  `cup_dropped_below_table`。
- 无 weld 且倾角 > `max_ungrasped_tilt_deg=75°` → `cup_excessively_tilted`。

已附着阶段（`RIGHT/LEFT_ATTACHED/LIFTED`）：
- weld 失活 → `{side}_grasp_lost`（P3 故障注入走这条，见 §8）。
- `_weld_error`（`task.py:399`）：计算当前 relpose 与 eq_data 设定值的偏差，若
  位置 > `slip_position_tolerance=0.025` 或角度 > `slip_angle_tolerance_deg=25°`
  → `{side}_grasp_slipped`。
- 杯底抬到 `table_top_z + lift_clearance=0.035` → 转入 `RIGHT/LEFT_LIFTED`。

稳定阶段：
- `WAIT_CENTER_STABLE`：条件 = 无 weld + 在中央区 + 直立 + 稳定 + 桌面接触 +
  右手无指接触；满足并**连续保持 `handoff_hold_seconds=0.25 s`** → 转入
  `WAIT_LEFT_GRASP`。
- `WAIT_GOAL_STABLE`：条件 = 无 weld + 在蓝区 + 直立 + 稳定 + 桌面接触 + 双手均无指接触；
  连续保持 `goal_hold_seconds=0.50 s` → `SUCCESS`。

`_hold_condition`（`task.py:449`）实现“连续保持”——条件不满足就清零计时器。

## 8. 故障注入：`inject_grasp_loss`（`task.py:443`）

显式关闭当前 weld 并记录 `injected_grasp_loss`，用于确定性地产出一条“抓取丢失”
失败视频。`p3_episode.py --mode both --seed 7` 会同时生成 success + failure 两条。

## 9. 运行器：`P3EpisodeRunner`（`p3_episode.py:60`）

- 提供 `_move_tcp/_move_joints/_set_gripper/_hold/_set_phase` 等原语（被 P4/P5 复用）：
  - `_move_joints`：在给定秒数内用 smoothstep 插值到目标关节角，每子步
    `controller.apply_action` 之外直接设 `target_joint_qpos` 并 `controller.step`。
  - `_move_tcp`：解 IK 得关节角再调 `_move_joints`。
  - `_set_gripper`：插值夹爪目标。
- `_run_success`（`p3_episode.py:445`）编排完整接力：初始化→右手接触夹取→
  抬升→中央物理放置→右手释放后撤→确认 `WAIT_LEFT_GRASP`→左手接触接力→
  蓝区物理放置→左手释放后撤→成功保持判定。
- 视频导出：主视角 + 俯视 + 实时状态面板（阶段、计时、事件、倾角），
  `imageio` 写 MP4；`summary` 写 JSON（含随机化、事件时间线、分阶段耗时、
  终点姿态/速度/接触）。

## 10. 运行命令与产物

```bash

MUJOCO_GL=egl .venv/bin/python -m openarm_mission.p3_episode --mode both --seed 7
# 不出视频，只跑状态机
.venv/bin/python -m openarm_mission.p3_episode --mode success --seed 7 --no-video
```

产物：`artifacts/p3/p3_{success,failure}_seed{NNN}.{mp4,json}`。
