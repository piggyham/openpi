# P0 · 冻结需求、坐标与动作接口

> 状态：✅ 已完成
> 作用：把整个任务的边界“冻结”下来——机器人、末端、物体、区域、顺序、动作维度、
> 安全约束和验收口径都在这一步定死，后续 P1~P8 都围绕这套口径实现，不得随意改。

## 1. 这一步要做什么

P0 不写代码，只做需求冻结。它回答六个问题：

1. 用什么机器人、什么末端、什么物体？
2. 物体从哪里取、放到哪里、谁先谁后？
3. 世界坐标怎么定义、单位是什么？
4. 策略给一个“动作”到底是几维、含义是什么？
5. 哪些动作必须被拒绝或限幅（安全）？
6. 怎样算这一阶段“做完了”（验收口径）？

冻结结果写在 `openarm_mission/SPEC.md` 与 `openarm_mission/config.py` 的
`MissionConfig` / `ControllerConfig` 中。

## 2. 冻结的范围（SPEC §1）

- **机器人**：OpenArm v1 双臂。
- **末端**：OpenArm v1 官方平行夹爪。
- **仿真器**：MuJoCo（主环境 2.3.7，客户端环境 3.2.3）。
- **物体**：空的、无把手、上宽下窄的一次性纸杯。
- **起点 A**：机器人右前方的红色圆形区域。
- **中转点**：桌面中央的金色圆形交接区域。
- **终点 B**：机器人左前方的蓝色圆形区域。
- **动作顺序**：右手 A 区取杯 → 中央直立放杯 → 右手退出 → 左手中央取杯 →
  B 区直立放杯 → 左手退出。
- **实现阶段**：P0~P4.5 已实现；P6~P8 为计划。

## 3. 坐标和场景约定（SPEC §2）

- 世界坐标单位：**米、弧度、秒**；`+z` 竖直向上。
- 从机器人朝桌面观察：`-y` 为右侧、`+y` 为左侧。
- 桌面中心 `(0.50, 0.00, 0.24)`，桌面上表面 `z = 0.28 m`。
- 红色 A 区中心 `(0.46, -0.20)`（右前）；中央交接区中心 `(0.50, 0.00)`；
  蓝色 B 区中心 `(0.46, +0.20)`（左前）。
- 三个任务区域在俯视相机中同时可见。
- 纸杯杯口直径 `70 mm`、杯底直径 `52 mm`、高度 `120 mm`；杯壁/杯底有效厚度 `2 mm`。
- 纸杯杯口直径小于夹爪最大张开包络 `88 mm`，两侧各留约 `9 mm` 余量 → 夹得稳。
- 纸杯标称质量 `35 g`；初始位置在 A 区半径 `15 mm` 内随机化，yaw 在 `[-π, π]`
  随机化；质量按标称值 `0.85~1.15` 随机化，滑动摩擦系数 `1.5~2.2` 随机化。

对应代码（`config.py`）：

```python
table_center            = (0.50, 0.0, 0.24)
table_half_size         = (0.38, 0.36, 0.04)   # 上表面 z = 0.24 + 0.04 = 0.28
region_a_center         = (0.46, -0.20)
handoff_center          = (0.50, 0.00)
region_b_center         = (0.46, 0.20)
cup_bottom_radius       = 0.026   # 52 mm 直径
cup_top_radius          = 0.035   # 70 mm 直径
cup_half_height         = 0.060   # 120 mm 高
cup_wall_thickness      = 0.002   # 2 mm
cup_mass                = 0.035    # 35 g
```

## 4. 上层控制接口：14 维双臂笛卡尔动作（SPEC §3）

每个策略动作是 14 维：

```
[ left_dx, left_dy, left_dz,   left_drx, left_dry, left_drz,   left_gripper,
  right_dx, right_dy, right_dz, right_drx, right_dry, right_drz, right_gripper ]
```

- 平移：**世界坐标系**下的末端增量，单位 **米**。
- 旋转：**世界坐标系**下的旋转向量增量，单位 **弧度**。
- 夹爪：归一化到 `[-1, +1]`；`-1` 完全张开，`+1` 完全闭合。
- 单次平移和旋转增量必须限幅（见 §5）。
- 左、右臂目标在**同一次** `apply_action()` 中更新——这是“双臂同步”的硬性要求。

> 注意左右顺序：前 7 维是左臂，后 7 维是右臂。这和后续 P5 的 state/action 顺序一致。

## 5. 底层控制管线与安全约束（SPEC §4–§5）

控制管线：

```
14D 双臂笛卡尔动作
  → 双臂目标末端位姿
  → 阻尼最小二乘 IK
  → 14 个目标关节角
  → 重力补偿关节 PD
  → MuJoCo 力矩执行器
```

- 常规策略动作用“位置 + 姿态”IK；跨区域展示轨迹可用“仅位置 IK”，让手腕姿态
  自动调整以扩大可达空间。
- 夹爪用位置目标；加载场景时统一官方左右夹爪 actuator 类型。

安全约束（P2 在 `ControllerConfig` 里落地，这里先冻结口径）：

- 拒绝错误维度、NaN、Inf 动作。
- 对单步平移、旋转、夹爪命令限幅。
- 末端目标做工作空间裁剪。
- IK 结果做关节限位裁剪，并保留限位边界余量。
- 单次关节目标变化限幅。
- 输出力矩使用官方 actuator force range。
- 关节速度越界进入制动模式。
- 不修改官方源文件；组合场景补充反射电机惯量和阻尼，抑制低惯量腕关节数值振荡。

## 6. P0~P2 验收口径（SPEC §6，节选）

- 官方 OpenArm v1 双臂模型可在 MuJoCo 2.3.7 与 3.2.3 中编译。
- 左右各 7 个关节、两个夹爪关节、两个 TCP site 均可解析。
- 桌面、红区、中央交接区、蓝区、无把手纸杯均存在；纸杯是开口锥台而非带把手马克杯。
- 控制器对非法动作失败关闭。
- 双臂近邻全位姿 IK 成功率 ≥ 98%（实测 40/40 = 100%）。
- 左右臂能通过位置 IK 到达各自任务区域。
- 物理步进中控制量始终有限，受官方力矩范围约束。
- 动态展示完整覆盖“右手取杯→中央放置→左手取杯→蓝区放置”，并导出
  MP4、GIF、三阶段故事板、JSON 成功摘要。

## 7. 可视化边界（SPEC §7，重要）

P0~P2 的动态展示中，机械臂用真实 MuJoCo 动力学与力矩控制；但**纸杯用“显式抓取
锁存”**（抓取后保持直立并跟随当前 TCP，释放时锚定到中央或蓝区），目的是稳定展示
已经完成的场景与控制流程。**不可用 P2 展示代替 P3 的物理抓取指标**——真正的物理
接触抓取在 P3 才出现。
