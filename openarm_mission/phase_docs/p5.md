# P5 · 轨迹采集与 LeRobot v2 转换

> 状态：✅ 已完成
> 作用：用 P4.5 纯摩擦专家当“人类示教者”，以 20 Hz 同步记录双臂关节/夹爪状态、
> 14 维笛卡尔动作、纸杯位姿、仿真时间和任务阶段，并随机化物理与视觉；再确定性
> 划分 train/validation/test，转换为 LeRobot v2 多模态数据集并支持回放。这一步
> 产出 P6 训练要吃的数据。

## 1. 这一步要做什么

1. 采集 20 条轨迹验证图像/状态/动作/时间戳对齐。
2. 检查双臂 state/action 单位、顺序、符号。
3. 采集 ≥200 条成功接力演示。
4. 加入位置、光照、材质、相机随机化。
5. 按种子划分 train/validation/test。
6. 转换为 LeRobot 数据集并实现 replay。

实现：`dataset.py`（schema、记录器、校验、JPEG 打包/解包）、`collect_dataset.py`
（批量多进程采集 + manifest/splits/alignment）、`convert_to_lerobot.py`、
`replay_dataset.py`。

## 2. 数据 schema（`dataset.py:63`，`schema_dict`）

固定 `fps=20`，时间戳用 MuJoCo 仿真时钟（秒）。

- **`observation.state`（16 维，float32）**：左臂 7 关节角（rad）+ 左夹爪平均开度
  （m）+ 右臂 7 关节角 + 右夹爪开度。顺序：`left_joint_1..7_rad, left_gripper_opening_m,
  right_joint_1..7_rad, right_gripper_opening_m`。
- **`action`（14 维，float32）**：左臂 `dx,dy,dz,dRx,dRy,dRz,gripper` + 右臂同。
  平移单位 m、旋转旋转向量 rad、夹爪归一化 `-1` 张开 / `+1` 闭合。
- **对齐语义**：`observation[t] -> action[t] -> target[t+1]`。即第 t 帧的 state，
  配上 expert 在该帧发出的 action，目标是第 t+1 帧的末端位姿。最后一帧保持零运动
  增量与当前夹爪命令。
- **`observation.cup_pose`（7 维）**：纸杯世界位姿 `x,y,z,qw,qx,qy,qz`。
- **`timestamp`（float64）**：MuJoCo 仿真时间。
- **`images`**：`front`、`left_wrist`、`right_wrist` 三相机，`uint8 [H,W,3]` RGB。
- **任务指令**（`TASK_INSTRUCTION`）：右臂把纸杯从红区移到中央，左臂再移到蓝区。

`episode_split(seed)`（`dataset.py:53`）：确定性 `seed % 10` —— 余 0→test，
余 1→validation，其余→train。200 条固定得到 160/20/20。

## 3. 记录器：`P5TrajectoryRecorder`（`dataset.py:210`）

继承 `FrictionScriptedExpert`，但**关掉展示视频**、改在控制帧上采样：
- `dataset_fps=20`、`runner_fps=20`，`_sample_stride = runner_fps // dataset_fps = 1`
  （每个控制帧采一次）。
- 构造时先 `apply_visual_randomization(mission, seed)` 做视觉随机化；建一个独立
  `_target_data = MjData(model)` 用于计算“目标位姿”；若 `capture_images` 建一个
  `mujoco.Renderer`（关掉 shadow/reflection/skybox/fog/haze，关掉 group 3+ 的
  密集碰撞 mesh 以加速 EGL 渲染）。

### 3.1 每帧采样 `_capture_sample`（`dataset.py:326`）
记：`timestamp`（仿真时间）、`state`（16 维，`_state`）、`target_positions/quaternions`
（`_target_poses`：把 `target_joint_qpos` 与 `target_gripper` 写进 `_target_data`，
`mj_forward` 后取双臂 TCP 位姿——这是 action 要对齐的目标）、`gripper_targets`、
`cup_pose`（7 维）、`stage`（状态机阶段）、`phase`（中文阶段名）、`images`（三相机）。

### 3.2 动作回算 `_actions`（`dataset.py:377`）
**action 不是直接读控制器命令，而是从相邻样本的目标位姿反算**，保证
`observation[t] -> action[t] -> target[t+1]` 严格成立：
- 平移 = `target_poses[t+1] - target_poses[t]`（左右臂各 3 维）。
- 旋转 = `_quaternion_delta_to_rotation_vector`（起点到终点的相对四元数转旋转向量）。
- 夹爪 = `_gripper_command(opening[t+1], config)`（把目标开度映射回 `[-1,1]`）。
- 最后一帧用自身做“下一帧”，得到零增量 + 当前夹爪命令。

### 3.3 视觉随机化 `apply_visual_randomization`（`dataset.py:108`）
不改任务语义，只改外观/相机：
- 主光位置在 `(0.5,0,1.4)` ±0.1/0.12 抖动，亮度 0.70~1.00，颜色 0.94~1.06 偏置。
- 桌面/纸杯/交接区材质亮度缩放。
- 三相机位置 ±0.025（前）/±0.004（腕）抖动，`fovy ±3°` 并 clip 到 `[35,90]`。
- 物理随机化由 expert 自带（XY/yaw/质量/摩擦/指垫摩擦/夹持力）。

## 4. 校验：`validate_trajectory`（`dataset.py:434`）

检查：state 形状 `(count,16)`、action `(count,14)`、cup_pose `(count,7)`、三相机
帧数一致；全有限；时间戳严格单调且与 `1/fps` 偏差 ≤ `1e-6`；动作平移 ≤
`max_translation_delta+1e-5`、旋转 ≤ `max_rotation_delta+1e-5`、夹爪 `|·|≤1+1e-6`
（控制器限幅的副本校验）；关节角/夹爪开度统计。`valid` 字段汇总。

## 5. 原始存储：`save_episode` / `load_episode`（`dataset.py:517`、`567`）

- 非图像字段直接进 `.npz`。
- 每个相机的帧序列逐帧 JPEG 编码（`quality=85, subsampling=1`），拼成一字节流
  `image_{cam}_jpeg_data` + 每帧偏移 `image_{cam}_jpeg_offsets`，避免存大量小文件。
- 原子写：先写 `.npz.tmp` 再 `replace`，并算 **SHA-256** 校验和。
- 同名 `.json` 元数据：版本、seed、split、task、fps、image_size、物理/视觉随机化、
  validation 报告、三套 config 的 `asdict`。

`load_episode` 反向解 JPEG 回 RGB 数组。

## 6. 批量采集：`collect_dataset.py`

`collect_dataset(episodes, workers, image_episodes, resume, max_new_episodes)`
（`collect_dataset.py:38`）：
- 先写 `schema.json`。
- `--resume` 时读旧 `manifest.json` 复用已成功且仍存在文件的 episode（按 seed
  对齐），只补采缺失的；打印 `resume: reusing N/M episodes`。
- `ProcessPoolExecutor(max_workers=workers, max_tasks_per_child=1)`（每进程跑一个
  seed 就退出，释放 EGL/内存），调 `_worker` 跑 `record_episode`。
- 前 `image_episodes` 条采三相机图像，其余只采 state/action（加速）。
- 写 `manifest.json`（episodes、successful_episodes、total_frames、all_valid、
  records[]）、`splits.json`（按 split 列种子）、`alignment_20.json`（前 20 条的
  图像—状态—动作—时间戳对齐验收报告）。

```bash
MUJOCO_GL=egl .venv/bin/python -m openarm_mission.collect_dataset \
  --episodes 200 --workers 16 --image-episodes 200
# 长采可分批
... --resume --max-new-episodes 32
```

产物：`artifacts/p5/raw/episode_seedNNNNNN.npz`(+`.json`)、`schema.json`、
`manifest.json`、`alignment_20.json`、`splits.json`。

## 7. LeRobot v2 转换：`convert_to_lerobot.py`

`convert_dataset(source_dir, output_dir, repo_id="local/openarm_paper_cup_relay")`
（`convert_to_lerobot.py:23`）：
1. 校验 `manifest.all_valid`；设 `HF_HOME` 到本地缓存。
2. 用 `LeRobotDataset.create(repo_id, root, robot_type="openarm_v1_bimanual", fps,
   features, use_videos=False, image_writer_threads=4)` 建空集。features 含
   `observation.state(16)`、`action(14)`、`observation.cup_pose(7)`、三相机 image。
3. 按 train→validation→test 顺序遍历有图像的 episode，逐帧 `add_frame`（state、
   action、cup_pose、三相机图、task 指令），`save_episode()` 收尾；每 10 条打印进度。
4. 写 `meta/info.json` 的 `splits`（按 episode 索引区间）、`meta/openarm_source_map.json`
   （LeRobot episode ↔ 源 seed/split/raw_path/SHA-256 反向映射）、
   `meta/openarm_conversion.json` 报告。
5. 重新 `LeRobotDataset(repo_id, root)` 加载校验：`num_episodes`/`num_frames` 与源
   一致。

```bash
.venv/bin/python -m openarm_mission.convert_to_lerobot
```

## 8. 回放：`replay_dataset.py`

`replay_episode(npz_path, output)` 从原始 `.npz` 解出三相机帧，按 20 fps 拼成 MP4
（主视角 + 左右腕），用于人工核对轨迹质量。

```bash
.venv/bin/python -m openarm_mission.replay_dataset \
  openarm_mission/artifacts/p5/raw/episode_seed000000.npz \
  --output openarm_mission/artifacts/p5/replay_seed000000.mp4
```

## 9. 验收结果（SPEC §16）

- 种子 0~199 共 200/200 条成功纯摩擦接力轨迹。
- 每条 432 帧、仿真时长 21.55 s，合计 **86,400 个 20 Hz 控制帧**。
- 200 条均通过有限值、形状、严格单调时间戳、动作限幅检查。
- 全部 200 条包含同步前视/左右腕 RGB；前 20 条对齐报告 20/20 有效。
- 划分 train/validation/test = 160/20/20。
- LeRobot v2 完整多模态集为 200 episodes / 86,400 frames，内部划分 160/20/20，
  本地重新加载和帧数核对通过。
