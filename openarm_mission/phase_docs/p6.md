## 2. openpi 的数据/推理抽象（要参照的既有代码）

接入前先理解四个既有抽象，它们就是 P6 要“照抄一份并改键”的地方：

1. **`transforms.DataTransformFn`**（`src/openpi/transforms.py`）：所有输入/输出
   变换的基类。`LiberoInputs`（`src/openpi/policies/libero_policy.py`）就是它的子类，
   把 LeRobot 里的 `observation/image`、`observation/state`、`actions`、`prompt`
   重打包成模型期望的 `{state, image:{base_0_rgb, left_wrist_0_rgb, right_wrist_0_rgb},
   image_mask, actions, prompt}`。

2. **`LeRobotLiberoDataConfig(DataConfigFactory)`**（`src/openpi/training/config.py:282`）：
   定义“数据集→训练/推理”的变换链。`create()` 返回：
   - `repack_transforms`：只在训练时把数据集键名映射到推理键名；
   - `data_transforms`：训练和推理都跑的 `Inputs/Outputs`；
   - `model_transforms`：tokenize prompt/action（由 `ModelTransformFactory` 生成）。

3. **`TrainConfig`**（`src/openpi/training/config.py:466`）+ `_CONFIGS`（`config.py:560`）：
   注册一个具名训练配置（`name`、`model`、`data`、`weight_loader`、`batch_size`、
   `num_train_steps`、`save_interval` 等）。`_CONFIGS_DICT` 按 name 索引。

4. **`serve_policy.py`（`scripts/serve_policy.py`）**：用 `tyro` 解析 `Args`，
   `EnvMode` 枚举（`ALOHA/ALOHA_SIM/DROID/LIBERO`）选默认 checkpoint，起
   `websocket_policy_server`。`create_trained_policy`（`policy_config.py:61`）按
   checkpoint 装配 `Policy`（模型 + transforms 链 + norm stats）。

## 3. 新增 `OpenArmInputs` / `OpenArmOutputs`

放在 `src/openpi/policies/openarm_policy.py`，照 `libero_policy.py` 抄一份改键。

**OpenArmInputs**（推理 + 训练输入）把 P5 的数据键映射到模型输入：

```python
@dataclasses.dataclass(frozen=True)
class OpenArmInputs(transforms.DataTransformFn):
    model_type: _model.ModelType

    def __call__(self, data: dict) -> dict:
        base_image   = _parse_image(data["observation/images/front"])
        left_wrist   = _parse_image(data["observation/images/left_wrist"])
        right_wrist  = _parse_image(data["observation/images/right_wrist"])
        inputs = {
            "state": data["observation/state"],            # (16,) 双臂关节+夹爪
            "image": {
                "base_0_rgb": base_image,
                "left_wrist_0_rgb": left_wrist,
                "right_wrist_0_rgb": right_wrist,
            },
            "image_mask": {  # 三相机全启用
                "base_0_rgb": np.True_,
                "left_wrist_0_rgb": np.True_,
                "right_wrist_0_rgb": np.True_ if self.model_type == _model.ModelType.PI0_FAST else np.False_,
            },
        }
        if "actions" in data:                              # 训练时才有
            inputs["actions"] = data["actions"]            # (14,) 笛卡尔增量+夹爪
        if "prompt" in data:
            inputs["prompt"] = data["prompt"]
        return inputs
```

要点：
- P5 已经是 delta action（`observation[t]->action[t]->target[t+1]`），与 π0 默认
  的 delta 语义一致，**不需要** LIBERO 里那种 `extra_delta_transform`。
- 状态 16 维直接喂模型（π0 内部会 pad 到 action 维度，见 `libero_policy` 注释）。
- 三相机正好对应 π0 的 base + 双 wrist，无需补零。

**OpenArmOutputs**：把模型输出（14 维归一化 action chunk）解归一化回
`[left dx..dz dRx..dRz gripper, right ...]`，夹爪符号 `-1` 张开 / `+1` 闭合 与
P5 一致；无需改顺序。若模型输出维度 > 14（如 pad 到 32），按前 14 维截取。

## 4. 新增 `LeRobotOpenArmDataConfig`

放在 `src/openpi/training/config.py`，照 `LeRobotLiberoDataConfig`（`config.py:282`）
抄：

```python
@dataclasses.dataclass(frozen=True)
class LeRobotOpenArmDataConfig(DataConfigFactory):
    @override
    def create(self, assets_dirs, model_config) -> DataConfig:
        repack = _transforms.Group(inputs=[_transforms.RepackTransform({
            "observation/images/front": "image",
            "observation/images/left_wrist": "left_wrist",
            "observation/images/right_wrist": "right_wrist",
            "observation/state": "state",
            "actions": "actions",
            "prompt": "prompt",
        })])
        data_transforms = _transforms.Group(
            inputs=[openarm_policy.OpenArmInputs(model_type=model_config.model_type)],
            outputs=[openarm_policy.OpenArmOutputs()],
        )
        model_transforms = ModelTransformFactory()(model_config)
        return dataclasses.replace(
            self.create_base_config(assets_dirs, model_config),
            repack_transforms=repack,
            data_transforms=data_transforms,
            model_transforms=model_transforms,
        )
```

`repack` 的键名必须和 `convert_to_lerobot.py` 里 `LeRobotDataset.create` 的 features
键（`observation.images.front` 等）以及推理时环境传给策略服务器的键一致——P6 要
在两端对齐这套命名。

## 6. 计算 normalization statistics

用 `src/openpi/shared/normalize.py` 的 `RunningStats`/`NormStats`：遍历训练集的
`observation.state`（16 维）和 `action`（14 维）累计均值/方差/q01/q99，存到
`assets/pi05_openarm_paper_cup_relay/norm_stats.json`。`create_trained_policy`
在推理时会从 checkpoint 的 `assets` 目录读它（`policy_config.py:88`，
`_checkpoints.load_norm_stats`），并对 state/action 做 `Normalize`/`Unnormal`
（`use_quantiles` 时用 q01/q99，鲁棒于离群）。

> 这是“策略输入输出记录”的前置：记录原始/归一化后的 state-action 便于调试。

## 8. 接入 14 维 action chunk、滚动重规划、双臂互锁

推理端要把 policy 的 **action chunk**（如 π0.5 一次输出未来 H 步 14 维动作）接到
`BimanualCartesianController.apply_action`：

- **滚动重规划**：每 `k` 帧重新查询 policy（不把整个 chunk 执行到底），让策略
  基于最新观察闭环修正。`sample_kwargs`（`policy_config.py`）控制 `sample_actions`
  的温度/步数。
- **双臂互锁**：复用 P3 状态机的 `RelayStage`——右手未完成中央释放并退出前，禁止
  左手进入交接区。策略不直接决定顺序，而是由环境状态机门控：若当前阶段不允许左臂
  动作，则把 action 的左臂 7 维置零（或 clamp 到零增量）。
- **安全限幅**：`apply_action` 已有平移/旋转/工作空间/关节限幅，policy 输出经它
  后天然安全；NaN/Inf 会被 `InvalidActionError` 拒绝。

## 9. 策略输入输出记录

`serve_policy.py` 已有 `--record` 选项；P6 扩展记录：每帧的原始 state、三相机图、
